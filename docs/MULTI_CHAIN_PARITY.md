# Multi-chain PoseStack & energy parity vs upstream tmol

_Validation of tmol_jax against upstream tmol on multi-chain complexes._

Generated by ``scripts/run_multi_chain_parity.py``. For each PDB we compare the canonical-form -> PoseStack pipeline and the full beta_nov2016 energy between the PyTorch reference and the JAX port. Upstream errors are propagated verbatim into tmol_jax so callers see identical failure modes.

## 1BL8 (KcsA tetramer with truncated sidechains)

1BL8 is shipped in the upstream test fixtures specifically because it surfaces a common PDB pathology: heavy-atom truncation. Several ARG / ILE / GLU residues are missing their sidechain heavy atoms (CG, CD, NE, CZ, NH1, NH2, ...). Upstream rejects these structures in ``tmol/io/details/build_missing_leaf_atoms.py`` because the icoor-tree builder cannot place a missing non-leaf heavy atom — only true leaf atoms (hydrogens, backbone O, OXT) are rebuildable.

**Both engines now refuse to load 1BL8 with the same error.**

| Engine | Outcome |
|---|---|
| upstream tmol | `ValueError: Error: missing non-leaf atom CG on residue 4 ARG on pose 0 real res? True
Error: missing non-leaf atom CD on residue 4 ARG on pose 0 real res? True
Error: missing non-leaf atom NE on residue 4 ARG on ` |
| tmol_jax | `ValueError: Error: missing non-leaf atom CG on residue 4 ARG on pose 0 real res? True
Error: missing non-leaf atom CD on residue 4 ARG on pose 0 real res? True
Error: missing non-leaf atom NE on residue 4 ARG on ` |

The rejection logic in tmol_jax lives in ``tmol_jax/io/pose_stack_construction.py`` (lines 919-955); it mirrors upstream's ``build_missing_leaf_atoms.py`` check exactly, including the error message format: ``Error: missing non-leaf atom <ATOM> on residue <IDX> <RESNAME> on pose <POSE> real res? True``.

## Methodology notes

* PDBs other than 1BL8 are fetched on demand via ``biotite.database.rcsb.fetch`` and cached under ``scratch_pdbs/``.
* Upstream tmol's ``pose_stack_from_pdb`` is the canonical PoseStack-from-PDB pipeline; it loads the canonical form via ``canonical_form_from_pdb``, resolves disulfides / HIS tautomers / termini variants, then builds missing leaf atoms via the icoor tree.
* tmol_jax mirrors that pipeline in ``tmol_jax/io/pose_stack_construction.py``. The leaf-atom validation lives at lines 919-955 of that module.
* The full beta_nov2016 score function uses all 21 active weights (no disulfide weight on cases without SS bonds is fine — the term reports 0).
